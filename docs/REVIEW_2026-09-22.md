## Findings (probe-confirmed)

1. **`python` resolution bug** — `finetune_start` invoked system python 3.14 (no torch/laya). Would have broken silently the day the RLCD loop landed. FIXED (sys.executable + venv fallback).
2. **CORS wide-open on localhost endpoint** — `allow_origins:["*"]` let any webpage POST to :8798 (drive-by inference). FIXED: middleware removed; same-origin policy now blocks browsers, local processes unaffected.
3. **Cold-start double-load race** — two concurrent first-calls could both load the 421M model (~1GB RAM each). FIXED: `threading.Lock` around agent loading.
4. **No training-job guard** — second `finetune_start` could clobber PROGRESS/pid. FIXED: running-pid check.
5. **Register doesn't verify the gate** — tool trusts the caller. PARTIAL: stamps "NOT VERIFIED" warning into registry; full enforcement deferred (needs eval output parsing once train.py is real).
6. **Process hygiene** — THREE serve.py generations accumulated (two stale + current), one serving pre-fix code while disk had fixes (identical-stale-traceback forensics). FIXED by port-owner kill + restart. **Operational rule: restart by port (`ss -tlnp` → kill), not cmdline grep.**
7. **Cold-start latency in MCP** — first `laya_predict` ≈ 20-25s inside the tool (model load). opencode timeout 60s OK; Claude Code default may not be. RECOMMENDED: `LAYA_PRELOAD` warmup flag at server start.

## Remaining recommendations (not blocking)
